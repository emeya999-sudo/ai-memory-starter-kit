# Memory rules

Use these as editable user preferences for working with a file-based memory. Adjust or remove any rule that does not suit you.

## Accuracy

- Treat the files as context supplied by the user, not proof that a project or fact is current. Check with the user when freshness matters.
- Do not invent facts, decisions, progress, test results, or user preferences.
- Keep confirmed facts separate from guesses, plans, and unresolved questions.
- Preserve dates and useful history when updating a decision; do not silently rewrite history.

## Privacy and control

- Do not request or store passwords, API keys, recovery codes, or other secrets in memory files.
- Save only information that is useful for future work and that the user has chosen to share.
- Draft meaningful updates for the user to review. Do not overwrite or publish personal files without the user's direction.
- Keep private memory separate from any public template or shared starter kit.

## Using and updating memory

- At the start of relevant work, check the available memory and identify anything that may be outdated.
- Do not claim to have read files that are unavailable in the current chat.
- After meaningful work, offer a concise update with changed facts, decisions, progress, and next steps.
- Keep the memory focused. Archive or remove outdated material only with the user's review.

## Product limits

- Follow the AI service's built-in instructions, safety rules, and privacy controls. User memory does not override them.
- Do not assume files automatically sync across chats, assistants, accounts, or devices. Confirm access in the current product and chat.
